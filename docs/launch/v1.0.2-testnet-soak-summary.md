## Known incidents

### 1. Explorer peer-wedge (2026-05-05) — RESOLVED

**Pathology:** explorer's `coincync-node` selected one peer for IBD, sent `GetBlocks`, peer responded with `Blocks` message containing 0 entries, request timed out, requeued. Same peer stayed selected, loop forever. Different IPs each occurrence; identical behavior. Two recurrences in 36h on the curated fleet (15.1.193.74 on 2026-05-04 / 5.4h, 75.82.181.240 on 2026-05-05 / 13h) confirmed it was not a fluke.

**Soak signal:** `stall_max = 46809s` (13h) on the explorer box, captured before the fix landed. Other 4 boxes max-stall ~40-45 min (normal block-time variance for a low-hashrate testnet).

**Fix:** [commit 28b3420](https://git.coincync.network/coincync/cync-protocol/commit/28b3420) — per-peer consecutive-empty-Blocks counter in `src/network/scoring.rs`. After 5 consecutive empties, peer is demoted in scoring and banned from `GetBlocks` selection for 1h. Auto-expires.

**Deployed:** mid-soak across all 5 fleet boxes. Post-deploy samples should show steady-state stalls ≤ 5 min.

**Verification:** 3 unit tests in `src/network/scoring.rs` pass; live fleet has not exhibited a new peer-wedge since the deploy.

### 2. No new incidents in the final 12h

The post-fix observation window (2026-05-06 14:00 UTC → 2026-05-07 02:48 UTC, ~13h) showed no new peer-wedge events on any box. Stall samples in this window stayed under 5 min on the explorer box, confirming the fix from commit 28b3420 took effect on the live fleet.
