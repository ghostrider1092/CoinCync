## Highest-value funds-correctness gaps (all MISSING)

1. **Full reorg-between-scans loop** through `scan_block_with_result` → `rewind_to_height` → rescan: no test drives the end-to-end removal of an orphaned received output or the un-marking of an orphaned spend. Only the rewind primitives and a separate rewind-based integration path (`tests/wallet_reorg_recovery.rs`) are covered — the ReorgDetected→rewind→rescan orchestration is untested.
2. **Lightsync loses `lock_height`** (`scanner.rs`/`lightsync.rs`): `OutputDigest` has no `lock_height` field, so `scan_output_digest` reconstructs `TxOutput { lock_height: None }`. A locked/vesting output detected on light sync would be counted as immediately spendable. No test guards this.
3. **Restore-from-seed subaddress gap limit** (`subaddress.rs::pregenerate_lookahead` + `wallet.rs::restore`): on a fresh restore `highest_used == 0`, so only `lookahead` addresses are pregenerated from index 1. Funds sent beyond the gap are silently missed. Untested in both directions (within-gap found / beyond-gap missed).
4. **Send↔receive derivation symmetry** for all five output kinds (main, subaddress, change, coinbase, coinbase-to-subaddress): no round-trip test builds an output via `send/assembly.rs` and confirms `scanner.rs` re-detects and decrypts it to the exact amount.
5. **Reservation lifecycle in `spend/submission.rs::submit_reserved`**: reserved-on-submit, released-on-Rejected, retained-on-Unknown/Accepted, and survives-crash (persisted `.reservations` sidecar) are entirely untested at the submission layer.
6. **Spend arithmetic invariant** `inputs == payments + change + fee` with the fee-growth re-selection loop and saturating overflow: not asserted in `send/prepare.rs`.
7. **Key-epoch rotation must not orphan** prior-epoch funds (`wallet.rs::derive_next_epoch`): untested.
8. **Real output actually placed in each ring** (`decoy_selection/allocation.rs`): spendability depends on the real member being present at the secret index — asserted nowhere.
9. **Watch-only spend detection** (`wallet.rs`): a watch-only wallet cannot derive key images, so it cannot mark its own outputs spent — the resulting balance-overstatement behavior is unpinned.
10. **Persistence partial-write / corrupt-sidecar** for `.history` and `.reservations` (only `.utxos` corruption, issue 90, is covered), plus the mid-write temp-file cleanup path in `save_v3_internal`.

Note: files present but outside the named scope (`background_sync.rs`, `churn.rs`, `history.rs`, `mnemonic.rs`, `node_rpc.rs`) were used for context only and are not enumerated above. There is no separate `view_keys.rs`; view-key types live in `keys.rs` (IVK/FVK/OVK) and `key_epoch.rs` (`ViewOnlyEpoch`, `ScopedViewKey`) and are covered under those headings.
