# Bug hunt — 2026-09-10 (canonical `main` @ d4ac445)

**Method.** Full unit-test run (`cargo test --lib --features testnet`: **1,206 passed, 0 failed, 7 ignored**) plus six independent read-only code reviews, one per subsystem (consensus, chain/reorg, mempool+tx, P2P network, wallet, crypto+storage). Every finding below required a traced code path and a concrete failure scenario. **None of these are caught by the existing test suite** — they are all logic/liveness defects the tests don't exercise.

**Confidence.** CONFIRMED = the exact code path was traced and is definitely wrong. PLAUSIBLE = likely, but one link could not be fully traced. Corroborated findings (hit independently by two reviewers) are marked.

Totals: **2 CRITICAL · 9 HIGH · 16 MEDIUM · ~11 LOW.**

## CRITICAL

### C1. ✅ FIXED (PR #109). Fork blocks are validated against the *main-chain* UTXO set, so the node can never reorg onto any branch that shares a transaction — permanent honest-node partition + mutual peer bans
`src/chain.rs:1968-1987` (all blocks, fork or not, run `validate_block_with_checkpoint_for_network(.., &inner.utxos, ..)` against the ACTIVE chain's UTXO set and return `Invalid` before the block is stored at `:2051/:2060`); `src/consensus/validation.rs:1589` (dup key image), `:1679` (dup stealth), `:1749` (ring member not found). The reorg loop `chain.rs:2738-2765` validates fork blocks correctly against rewound state — but only ever sees blocks that already passed the main-state pre-check.

**Scenario — an ordinary natural 1-block fork:** mempool tx X (key image K) is mined by two miners into M(n+1) and F(n+1). Node A accepts M(n+1); receiving F(n+1) it validates against a UTXO set already containing K → `Invalid("duplicate key image")`, never stored. F(n+2), F(n+3)… return `Orphan` forever; orphan replay re-rejects F(n+1). Node A stays on M regardless of F's work; Node B does the mirror. Each `Invalid` scores `InvalidBlockProofs` (2-strike ban) so the two honest sides ban each other. No recovery: `rollback_to_height` has no production caller; `force_resync` re-downloads without rewinding. Also fires for fork blocks whose decoys include fork-only outputs, or whose re-mined tx creates outputs already indexed from main.

Why tests miss it: `tests/sim_l3_consensus.rs` and `tests/chaos_partition_l6.rs` use coinbase-only fork blocks (no key images / ring members). **CONFIRMED.**

Fix: for `!is_main_chain` blocks, run only context-free checks (PoW, header, structure, fork-window difficulty) before storage and defer UTXO-dependent checks to the reorg loop — or validate against a UTXO view rewound to the fork point.

### C2. One non-reading peer freezes ALL P2P message processing, then evicts every honest peer via the memory budget — total P2P outage from a single TCP connection
`src/network/node/runtime.rs:191-248` (one sequential task processes every peer's messages); `src/network/node/broadcast.rs:232-241` (`send_to_peer` awaits a bounded(100) channel); `src/network/node/connection.rs:459-509` + `src/network/framing.rs:505-516` (write path has **no timeout**; only reads do). Request handlers (GetBlocks `dispatch/chain.rs:91`, GetData `:564-569` up to 500 blocks, GetHeaders `dispatch/headers.rs:273`) send one-by-one.

**Scenario:** attacker connects (Verack alone suffices — see M-P1), sends 3×GetBlocks of 500 hashes (within rate limit) or one GetData of 500, then stops reading its socket. TCP buffer fills → write arm blocks forever → channel fills → the global processor blocks inside `send_to_peer` forever. Every other peer's task blocks on `msg_tx.send` (`connection.rs:442`). The maintenance loop (`maintenance.rs:266-268`, `:317-323`) uses sequential awaited sends, so the 300s stale-peer sweep that would remove the attacker never runs. Second-order: queued messages hold `MemoryReservation`s until processed (`node.rs:82-87`); other peers' reads hit the 50 MB budget → `P2pMemoryBudgetExceeded` (`framing.rs:335-342`) → `connection.rs:451-454` disconnects the **honest** peers. Persists until restart. **CONFIRMED.**

Fix: write timeout on the framer; per-peer send tasks (or `try_send` + disconnect-on-full) so one slow peer can't block the processor; make the memory-budget failure evict the offending queue, not the reader.

## HIGH

### H1. Header-version ratchet: one mined block with `version=255` permanently bricks every honest miner's templates
`src/consensus/validation.rs:1029-1034` (`version < prev.version` → reject), `:997-1005` (version is a *minimum* only), mirrored `src/network/node/dispatch/headers.rs:117-118`. Builder `src/mining/block_builder.rs:274` emits `block_version_at_height` (1, then 2 at 50 000). No upper bound anywhere. One valid block with version 255 → every subsequent honest block is rejected "version cannot decrease v255→v1" by every node including the miner's own. Cost: one block. **CONFIRMED.** Fix: cap `header.version` at the max known version (reject unknown versions) or drop the monotonic rule.

### H2. Coinbase is exempt from the duplicate-stealth-address rule, and reorg disconnect deletes a *shared* index entry unconditionally → a victim's output vanishes on reorged nodes (cross-node divergence + frozen funds) — CORROBORATED (consensus + storage reviewers)
`validation.rs:1293` (coinbase returns `Ok` before output checks); `:1669-1686` (dup-stealth-vs-chain check only on the non-coinbase path; `:573-586` is within-block only); `src/storage/utxos.rs:165-176` (`or_insert`, oldest wins — colliding coinbase silently shares the victim's entry); `utxos.rs:320-336` (`remove_output` deletes `stealth_index`/`output_index` in memory **and on disk** without checking the entry points at the block being removed).

**Scenario:** attacker-miner mines block B whose coinbase output reuses victim output V's stealth address S (passes: amount/commitment only). Any 1-block reorg that disconnects B → `remove_output` deletes S's index entry → V unfindable on reorged nodes but present on others. A later tx using V as ring member: rejected on reorged nodes (height ≥ 100), valid elsewhere → chain split; V unspendable on the reorged side. ~3 blocks of PoW, any network, any height. **CONFIRMED.** Fix: apply the dup-stealth check to coinbase; make `remove_output` only remove an index entry that references the output being removed.

### H3. Failed-reorg rollback (path A) leaves stale `height_to_hash` for fork heights above the old tip → a follow-up block commits a chain with an unapplied gap
`src/chain.rs:3044-3047` bounds removal by `inner.tip.height.max(pre_reorg_tip.height)`, but `inner.tip` isn't advanced until `:3313`, so fork blocks connected at heights > old tip keep their mapping (path B `:3224-3228` does it right). Immediately: RPC/sync report F(n+1) as canonical while tip = M(n). Exploit: a follow-up coinbase-only block T2 with parent F(n+1) makes `find_fork_point` (`:4093-4096`) return `fork_point = n+1 > tip`; empty disconnect, empty fork chain, T2 validates against main → commits tip T2@n+2 with UTXO/supply still reflecting M and no row for n+1. Realistic at the difficulty floor where both difficulty checks agree. **CONFIRMED (stale mapping) / PLAUSIBLE (full exploit).** Fix: bound path-A removal by the highest fork height actually applied.

### H4. Unsolicited `Blocks`/`BlockData` orphan flood: free reputation, inline RandomX CPU burn, ~2 GB orphan pool, poisoned sync queue, honest peers GetBlocks-banned
`dispatch/chain.rs:308-498`, `:587-700` (unrequested blocks accepted; only PoW gate is against the **peer-supplied** target — `0xFF..` passes anything; not rate-limited, 16 MB/500 blocks); RandomX hashed inline on the processor task `:449-458`; `record_block_success` `:490-496` (+2 rep, resets the empty-ban counter); `src/chain.rs:1885-1892` returns `Orphan` **before** PoW/difficulty validation; `sync.rs:1039-1131` stores bodies in a 1000-entry LRU (evicting honest orphans; up to ~2 GB), pushes attacker parent hashes to the front of `pending_headers`, forces `state=Blocks`; `sync_driver.rs:457-506` requests the garbage from honest peers, who reply empty and get GetBlocks-banned after 5 (`scoring.rs:649-673`); timed-out garbage is re-pushed to the front, so IBD wedges. **CONFIRMED.** Fix: don't accept unrequested blocks (or verify against our expected target), don't orphan-store before PoW validation, rate-limit Blocks.

### H5. Single-flight GetHeaders slot is captured indefinitely by Verack replay → IBD wedge
`sync.rs:1234-1244` (one global slot, freed on any Headers reply incl. empty — not scored); `dispatch/control.rs:303-371` (`handle_verack` has no state precondition, re-grabs the slot whenever `peer.height > ours`; Verack not rate-limited; `peer.height` uncapped from `Version.start_height`). Attacker sends `Version{start_height: u64::MAX}` then Verack ~50/s, answering each GetHeaders with empty Headers → honest peers essentially never get a slot. Same lever via `InvBlock`. **CONFIRMED.**

### H6. `ChainWork` over-claim flips `is_synced()` false indefinitely — gates the miner off — with no substantiation requirement
`dispatch/control.rs:251-301` → `sync.rs:393-438` (cap is 2× the observed max, which ratchets on the attacker's own accepted claim); `node.rs:490-491`, `sync_driver.rs:171-176` → `set_work_behind(true)` vetoes `is_synced()` (`chain.rs:1308`), consumed by the mining gate (`bin/node.rs:1643`). Anti-wedge is only a 600s TTL (attacker re-sends), a ban that needs 3 failed *block* requests (never happen — empty Headers), and an unwired `retain_connected_peers`. One connection per node sending `ChainWork{td: local×2}` every 4 min → every miner gated off, GetHeaders spammed 2/s forever. **CONFIRMED (flip) / PLAUSIBLE (miner halt).** Note: this is the different-tip case the PR #100 review explicitly called out as unaddressed.

### H7. Address book: peer-supplied timestamps drive eviction and dial order → outbound dial starvation / full-book takeover
`dispatch/address.rs:118-132` (accepts `timestamp ≤ now+600` as `last_seen`); `bootstrap.rs:440-447` (evicts smallest `last_seen`), `:499-508` (dials largest first); no port-0 filter (`address_policy.rs:6-16`); keyed ip:port so one IP fills its /16 quota with ports; `peer_manager.rs:339, 409-500` (one address per 10s tick; subnet-cap/dup hits burn the tick). One `Addr` of 250 future-dated entries → ~40 min of wasted ticks before any honest dial; `clear_tried` (fired every 120s under H5/H6 stalls) restarts it; with 8 netgroups the whole 1000-entry book can be replaced, anchors become attacker peers, DNS seeds only consulted when the book is empty. **CONFIRMED mechanics / PLAUSIBLE eclipse.**

### H8. Mempool eviction off-by-one: a *rejected* tx evicts 100 honest resident txs for free (repeatable griefing)
`src/mempool.rs:655-691` (simulation permits exactly 100 evictions) vs `:707-750` (real loop returns `Err(MempoolFull)` on the 100th eviction even though the tx now fits). Attacker tunes a valid tx to need exactly 100 evictions (byte-exact via unbounded `extra`, see M1): each submission drops 100 low-fee txs + any RBF replacements, is rejected (never mined, zero cost), same UTXO reusable forever. **CONFIRMED.** Fix: test fit before the attempt cap (make the cap `>` in one place).

### H9. Wallet: reorgs between `wallet scan` runs are never detected → orphaned outputs/spends persist as wallet state
`src/bin/wallet_support/legacy.rs:1224-1225` builds a fresh `WalletScanner` with an empty journal every run, never `set_position`; `scanner.rs:901-911` (only reorg signal is `journal.back()` = None); `persistence.rs:500-526` persists `scanned_height` but **no block hash**. Output O received in an orphaned block stays a spendable UTXO (over-reported balance; spends fail with `RealOutputIdentityMismatch`). Mirror: our spend of U confirmed in an orphaned block → `spent=true` persisted, reservation cleared; if not re-mined, U is permanently invisible barring a manual deep `--from` rescan. Applies at *any* reorg depth across runs. **CONFIRMED.** Fix: persist the scanned tip hash and verify continuity on resume.

## LOW

- **RBF has no absolute-fee rule** (25% *rate* bump only): a 500 KB tx can be replaced by a 1.5 KB one paying ~1/300 the fee → relay-bandwidth griefing (BIP125 rules 3/4). `mempool.rs:623-637`.
- **Dandelion stempool** dedups by tx hash only, count-bound only (10 000 × 500 KB ≈ 5 GB); one UTXO → unlimited conflicting stem txs evicting other peers' in-flight txs. `dandelion.rs:307-360, 518-543`.
- `fee_percentiles` mixes scaled and raw fee units (latent; no consumer yet). `mempool.rs:1029-1064`.
- Coinbase structural fields unvalidated: dead `!inputs.is_empty() && !is_coinbase()` check; arbitrary inputs/fee/range_proof/extra allowed (bloat); curve-point check skipped for coinbase (identity stealth → unspendable decoy-set pollution); 1-atomic outputs accepted. `validation.rs:345, :1303, :362-375`.
- Wall-clock "timestamp too far in future" scored as instant ban → a 10-min clock lag permanently bans an honest relayer (Bitcoin deliberately doesn't). `validation.rs:1105`; `scoring.rs:212`.
- Request amplification headroom: GetBlocks 16 KiB→16 MB, GetHeaders loads up to 2000 *full blocks* from DB; ~1000× before any penalty (feeds C2). `headers.rs:249-270`.
- Fork blocks never evicted from `inner.blocks` (hashpower-bounded RAM leak; accelerates canonical eviction). `chain.rs:2051, :168-204`.
- `ShieldedStore::append_commitment` ignores `BridgeTree::append`'s `false` and overwrites the last leaf (docstring claims a panic). Needs 2^32 leaves. `shielded.rs:264-273`.
- `ShieldedStore`/`SparkStore::rewind` discard on-disk delete errors (`let _ =`) → replayed root can silently diverge from the committed header root. Stores dormant today. `shielded.rs:485-492`; `spark.rs:362-369`.
- `wallet scan --from H` past the tip sets `scanned_height=H`, skipping real blocks on the next default scan. `legacy.rs:1276-1285, :1431`.
- Parallel coinbase scan path lacks the commitment ghost-balance check and bypasses the journal (test-only callers). `scanner.rs:1150-1206`.
- Latent/dead: key-epoch rotation would orphan outputs (`derive_next_epoch` has no callers); vesting builder violates the uniform tx shape (no CLI caller); legacy `cmd_send` marks spent on mempool-accept (unreachable via v2).

## Suggested fix order
1. **C1** (fork validation vs main UTXO) — the network cannot survive an ordinary fork with a shared tx. Highest priority.
2. **C2** (single slow peer freezes P2P) + **M-P1** (handshake bypass, which makes C2/H4/H6 trivially reachable).
3. **H1** (version ratchet) — one-block network stall, trivial fix (cap the version).
4. **H2 + M6** (coinbase dup-stealth + unconditional index removal + pre-commit disk delete) — fix together; they share `remove_output`.
5. **H4, H5, H6, H7** (P2P liveness/sync/eclipse) — one hardening pass over `sync.rs` / `dispatch/*` / `bootstrap.rs`.
6. **H8 + M1** (mempool eviction off-by-one + unbounded `extra`) — fix together; M1 enables H8.
7. **H3, M10** (reorg rollback stale mapping + cache-only disconnect).
8. **H9, M7, M8** (wallet reorg/restore/watch-only correctness).
9. The rest of MEDIUM, then LOW.
