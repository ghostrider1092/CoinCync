Building from Source

Prerequisites

  • Rust toolchain (stable): https://rustup.rs
  • CMake (for native dependencies)
  • Linux: apt install build-essential cmake pkg-config libssl-dev
  • macOS: xcode-select --install && brew install cmake
  • Windows: Install CMake from https://cmake.org and Visual Studio Build Tools

Build All Binaries

cargo build --release --features testnet

This builds three binaries in target/release/:

BinaryPurpose
`coincync-node`Full node daemon (P2P, RPC, mining)
`cync-tui`Terminal dashboard (wallet, explorer, mining viz)
`cync-wallet`CLI wallet (create, send, receive, assets)

Running a Node

Quick Start

# Create data directory
mkdir -p ~/.coincync/testnet

# Start node with mining
./target/release/coincync-node \
  --network testnet \
  --data-dir ~/.coincync/testnet \
  --mine \
  --mining-threads 1 \
  --mining-address YOUR_WALLET_ADDRESS

Creating a Wallet

Using cync-wallet CLI

# Create wallet directory
mkdir -p ~/.coincync/wallets

# Create a new wallet
./target/release/cync-wallet \
  --wallet mywallet \
  --network testnet \
  create

# You'll be prompted for a password and shown a 24-word seed phrase
# WRITE DOWN THE SEED PHRASE - it's the only way to recover your wallet

Wallet CLI Flags

`--wallet`—Wallet name (stored in `~/.coincync/wallets/<name>.cync`)
`--wallet-file``~/.coincync/wallet.cync`Full path to wallet file
`--network`mainnetNetwork: `testnet` or `mainnet`
`--daemon`autoNode RPC address (`host:port`)
`--no-tls`offDisable TLS for RPC
`--password`—Wallet password (prefer env `CYNC_WALLET_PASSWORD`)

Wallet Commands

# Show address
cync-wallet --wallet mywallet --network testnet address

# Show balance (needs running node)
cync-wallet --wallet mywallet --network testnet --daemon 127.0.0.1:28081 --no-tls balance

# Send CYNC
cync-wallet --wallet mywallet --network testnet --daemon 127.0.0.1:28081 --no-tls \
  send RECIPIENT_ADDRESS 10.0

# Create subaddress
cync-wallet --wallet mywallet --network testnet subaddress new --label "donations"

# List subaddresses
cync-wallet --wallet mywallet --network testnet subaddress list

# Restore from seed
cync-wallet --wallet restored --network testnet restore "your 24 word seed phrase here"

# Interactive shell mode
cync-wallet --wallet mywallet --network testnet --daemon 127.0.0.1:28081 --no-tls shell

Connecting the TUI

The TUI is a full terminal dashboard that connects to a running node via RPC.

Watch-Only Mode (no wallet)

View blocks, peers, mining stats, and network health:

./target/release/cync-tui --node 165.22.173.168:28081 --no-tls --network testnet

Full Mode (with wallet features)

Pass --api-key to enable wallet tabs (balance, send, receive, assets):

./target/release/cync-tui \
  --node 165.22.173.168:28081 \
  --no-tls \
  --api-key test \
  --network testnet

Note: The node must have a wallet loaded (--faucet-wallet flag) for wallet RPC methods to work.

Testing Privacy Features

1. Ring Signatures (CLSAG)

Every transaction uses ring signatures to hide the true sender among decoys.

# In TUI: press 's' to send
# Enter a recipient address and amount
# The transaction automatically includes ring decoys from the blockchain

What to observe:

  • Transaction has multiple input public keys (the ring)
  • Only one is the real sender — outsiders can't tell which
  • Ring size increases as the chain grows (min 11 at maturity)

2. Stealth Addresses

Every transaction creates a one-time stealth address for the recipient.

# Send to the same address twice
# Each transaction creates a different on-chain output address
# Observers cannot link the two payments to the same recipient

What to observe:

  • The on-chain stealth_address differs for each output
  • Only the recipient (with their view key) can detect the payment
  • View tags provide fast scanning without revealing the link

3. Subaddresses

Create unlinkable receive addresses from a single wallet.

# In TUI: press 'n' to create a new subaddress
# Or CLI: cync-wallet subaddress new --label "shop"
# Give different subaddresses to different senders

What to observe:

  • Each subaddress is cryptographically derived but unlinkable
  • All subaddresses deposit to the same wallet
  • Senders cannot determine if two subaddresses belong to the same wallet

4. Confidential Amounts (Pedersen Commitments + Bulletproofs)

All transaction amounts are hidden using Pedersen commitments.

# Send any amount — the amount is never visible on-chain
# Only the sender and recipient know the true amount
# Bulletproofs prove the amount is valid (non-negative, no overflow)

What to observe:

  • On-chain outputs show commitment (32 bytes) instead of plaintext amounts
  • range_proof (Bulletproof) proves validity without revealing the amount
  • Validators verify commitments balance without seeing values

5. Confidential Assets

Issue and transfer custom assets with hidden asset types.

# In TUI: press 'i' to issue a new asset
# Enter name, precision, and initial supply
# Press 'A' to send the asset to another address

What to observe:

  • Asset type is hidden behind an asset_commitment
  • Asset surjection proofs (1-of-n ring) prove the output asset is one of the allowed types
  • Observers cannot tell which asset type is being transferred

6. Dandelion++ Transaction Routing

Transactions propagate through a "stem" phase before broadcasting.

# In TUI: press '5' for Network tab
# Look for Dandelion++ stats
# Transactions first travel along a random stem path, then fluff to all peers

What to observe:

  • Stem peers: transaction relayed privately through 1-2 hops
  • Fluff phase: transaction broadcast to the network
  • Observers cannot determine which node originated the transaction

7. Time-Locked Transfers (Vesting)

Lock funds until a specific block height.

# In TUI: press 'v' to vest
# Enter recipient, amount, and unlock height
# Funds cannot be spent until the chain reaches that height

What to observe:

  • Output has a lock_height field
  • Wallet shows locked vs unlocked balance separately
  • Attempting to spend before unlock height fails consensus validation

Running Your Own Seed Node

Full setup guide for a DigitalOcean/VPS server.

1. Server Requirements

  • 2+ GB RAM (4 GB recommended for Rust builds)
  • 25+ GB disk
  • Ubuntu 22.04 or later
  • Open ports: 22 (SSH), 28080 (P2P), 28081 (RPC)

2. Install Rust and Dependencies

apt update && apt install -y build-essential cmake pkg-config libssl-dev git
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env

3. Clone and Build

git clone https://git.coincync.network/coincync/cync-protocol.git /opt/coincync
cd /opt/coincync
cargo build --release --features testnet

If the build gets killed (OOM on 2 GB servers), add swap:

fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
# Retry the build
cargo build --release --features testnet

4. Create Wallet

mkdir -p ~/.coincync/wallets
cd /opt/coincync
./target/release/cync-wallet --wallet mynode --network testnet create --password YOUR_PASSWORD
# Save the seed phrase!
# Note the address (starts with CYNC or tCYNC)

5. Start the Node

nohup ./target/release/coincync-node \
  --network testnet \
  --data-dir /data/coincync \
  --mine \
  --mining-threads 1 \
  --mining-address YOUR_WALLET_ADDRESS \
  --no-p2p-encryption \
  --rpc-bind 0.0.0.0 \
  --no-rpc-tls \
  --faucet-wallet ~/.coincync/wallets/mynode.cync \
  --faucet-password YOUR_PASSWORD \
  > /var/log/coincync-node.log 2>&1 &

6. Monitor

# Live log
tail -f /var/log/coincync-node.log

# Check if running
pgrep coincync-node

7. Connect TUI Remotely

From your local machine:

cync-tui --node YOUR_SERVER_IP:28081 --no-tls --api-key test --network testnet

Troubleshooting

Build fails with OOM (Killed/SIGKILL)

Rust release builds need 3-4 GB RAM. Add a swap file:

fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile

Nodes not peering (Noise handshake failed)

Add --no-p2p-encryption to all nodes. The Noise protocol encryption handshake can fail between nodes; disabling it allows plaintext P2P connections for testnet.

"Failed to create wallet: No such file or directory"

Create the wallets directory first:

mkdir -p ~/.coincync/wallets

critical_files.lock hash mismatch

If you modify consensus-critical files, update the lockfile:

# Compute new hash
sha256sum src/testnet.rs
# Edit critical_files.lock with the new hash

ASERT integer exponent clamped

Normal on fresh chains. The difficulty algorithm clamps extreme adjustments when the genesis timestamp is far from the current time. This resolves as the chain grows.

Self-connection detected

Normal. The node discovers its own IP in the seed list and correctly rejects the connection.

TUI shows no wallet data

Make sure:

1. The node was started with --faucet-wallet and --faucet-password

2. The TUI was started with --api-key (any value works when auth is disabled)

3. RPC is reachable: curl http://NODE_IP:28081 should respond
