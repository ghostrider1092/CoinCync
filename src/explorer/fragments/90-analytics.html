Home›Privacy features
CoinCync privacy features
What every CYNC transaction gets, by default, without an opt-in toggle. Privacy is a stack — each layer below handles a different attack surface, and they compose.
What stays private on every transaction
Who you sent it
CLSAG-11 ring signatures
Every input is signed by a ring of 11 candidate spenders. A chain observer sees a possible-spender set, never the actual one. Decoys are drawn from the full UTXO pool by a uniform selector — no recency bias to single out the real signer.
Who received it
Stealth addresses + view tags
Each output is a fresh one-time address derived from the recipient's view key + a per-tx ephemeral key. The recipient's on-chain "address" appears nowhere on chain. View tags let wallets scan efficiently without weakening unlinkability.
How much
Pedersen + Bulletproofs+
Amounts are homomorphically committed — the chain verifies inputs balance outputs without seeing either value. Bulletproofs+ prove every output is in the valid range without revealing the amount.
What it's for
Encrypted memos
Optional payment metadata, encrypted to the recipient via ECDH + ChaCha20. Visible only to the recipient's view key — the chain stores ciphertext, no one else can decrypt.
Network-level privacy
First-hop unlinkability
Dandelion++
Transactions propagate through a random stem of one hop per epoch before fluffing to the whole graph. A surveilling peer can't tell whether the tx originated with you or was just relayed.
Wire-level encryption
Noise_XX P2P
Every peer connection is encrypted + authenticated end-to-end with the Noise protocol. ISPs, network observers, and intermediate relays see ciphertext, never plaintext blocks or txs.
Traffic-shape defense
Constant-rate padding
Cover packets at a constant rate make it impossible to correlate node activity with transaction events through timing analysis. The wire looks busy whether or not you've just sent.
Operator IP
Tor / SOCKS5 transport
First-class support for routing the node through Tor or any SOCKS5 proxy. Operators can run a public-facing node without revealing their physical IP.
Defense in depth — reorg resistance
Six independent layers protect the chain from reorganization attacks. Each one alone is solid; together they make deep reorgs effectively impossible without producing more PoW than the rest of the network combined for hundreds of blocks.
L1–3: MESS hybrid
PoW-weight + difficulty-adjustment-aware penalty + max-reorg-depth cap. Tier-3 caps any candidate reorg at 200 blocks.
L4: per-node rolling checkpoints
Each node's own paranoia sentinel every 5 blocks. Zero consensus impact.
L5: hardcoded checkpoints
Cut by the release pipeline. Defends the chain past the most recent release.
L6: CIP-009.D rolling-finality
Miner-signed checkpoints, dormant at v1.0 launch, activatable post-mainnet via CIP-007.
Wallet: bounded rewind journal
200-entry BlockApplyDiff journal in every wallet. Detects + recovers any reorg up to tier-3 depth without a full rescan.
Economic posture
No founder allocation
0 % premine · 0 % dev tax
Every CYNC in circulation was mined fairly from genesis forward. Article XII of the Constitution makes any future allocation a hard-fork action requiring node-operator consent.
Tail emission
100 M cap, 0.6 CYNC tail
Block reward floors at 0.6 CYNC forever, so miners stay incentivized to keep securing the chain after the cap is approached.
Fee burn
30 % / 50 % split
A fraction of every transaction fee is burned, reducing supply over time even with tail emission. The burn rate scales with congestion.
CPU-friendly mining
RandomX (memory-hard)
Memory-hard PoW algorithm hand-tuned to resist ASIC + FPGA acceleration. Mining stays accessible to anyone with a modern laptop.

Consensus-mandated privacy
Confidential amounts
Every transaction output value is hidden behind a Pedersen commitment. The chain validates a Bulletproofs+ range proof per output, but only the prover and recipient learn the actual amount.
—
Stealth addresses
Recipients publish a (view, spend) pubkey pair; senders derive a one-time output key per transaction. No on-chain link between sender and recipient address.
—
What you're looking at
These pools coexist with CoinCync's always-on per-tx privacy (CLSAG ring signatures + Bulletproofs+ + stealth addresses, all mandatory at consensus). They're additional surfaces planned for Phase 2 of the privacy stack:
  • Spark (CIP-005) — single-curve shielded coin scheme; transactions ship post-mainnet. The accumulator is live for observability today.
  • Shielded pool — zk-SNARK style note commitment tree (Halo2 lineage). Storage layer in place; full spend/verify queued.
  • MW cut-through — MimbleWimble-style kernel compression. Engine is live and accumulating state.
Per the staged-mainnet decision, full transaction flow for each pool ships behind its own dedicated audit. This page exists so users can see the cryptographic state before, during, and after each pool's full activation.
