Layer 3+ — M-of-N multisig (CIP-008, new this phase)

FROST signing coordinator. Untrusted message-relay service that lets multisig participants exchange round-1 commitments and round-2 sig-shares without manual copy-paste. The coordinator holds zero key material — even a malicious or compromised coordinator cannot forge signatures or steal funds. Worst case: a session fails to complete and participants retry.

Shipped as the coord WSS server + coord-cli operator binary. State machine, HMAC invitation tokens, JSON file persistence, per-IP rate limit, idle-connection timeout, and Prometheus metrics endpoint all live. The signing protocol is RFC 9591 FROST over Ed25519 via frost_ed25519; the coordinator is the off-chain message relay.

Status: CIP-008 Draft · spec → · CIP-012 deployment plan →

Layer 4 — Cross-chain (CIP-001, new this phase)

CYNC↔BTC atomic swap. Trustless cross-chain swap modeled on the Comit / Farcaster XMR↔BTC design. Adaptor signatures over CLSAG keep the swap invisible on the privacy chain — an observer sees a normal CoinCync transaction, not a swap. Bitcoin side uses Schnorr/ECDSA adaptor signatures over secp256k1; the two adaptors are bound by a cross-curve discrete-log-equality proof. Either party can refund unilaterally if the counterparty disappears (asymmetric timeouts).

Shipped this phase: protocol state machine (Negotiated → AliceLocked → BobLocked → SecretRevealed → Completed, with refund + abort terminal states), handshake state machine + wire-format messages, SwapStore JSON state persistence with atomic writes, and the cyncswap CLI driving all of them. Hard mainnet-launch blocker per Article XV. The cryptographic core (real adaptor sigs + Tor/Noise transport) and the audit are queued for the post-testnet window.

Status: CIP-001 Draft (mainnet blocker) · spec →

Layer 4 — Light-wallet SPV (lightsync, new this phase)

Server-blind compact-block sync. Wallets that don't run a full node download per-block OutputDigest bundles (~138 B / output) and scan locally with view-tag filtering. The server learns only the height range the wallet asked for — never which outputs the wallet cares about, never the wallet's address set. Strictly stronger privacy than BIP-157, where the wallet's filter elements leak its address set to the filter server.

Shipped this phase as the get_output_digests + get_sync_checkpoints JSON-RPC methods and the GetOutputDigests P2P message handler. Pull-protected (max 100 blocks per request). Wallet-side scanning uses the existing CLSAG ECDH + view-tag fast-path.

Layer 5 — Reorg defense (CIP-009 family)
FeatureProtectsStatus
Path B — consensus checkpointsReorgs past project-cut checkpoints (cold horizon)shipped
Path D — miner-signed rolling checkpoints (CIP-009.D)Reorgs past the live tip (~100 blocks deep) once 2/3 of active miners attestshipped behind rolling-finality feature flag

Path D replaces the rejected MESS approach with discrete miner attestation. Each block carries an ed25519 signature over a past height/hash from the producing miner; a height becomes soft-final once 2/3 of active miners (with at least one block in the last ~14 days) have signed it. No clock readings, no decay-tuning knobs, observable on-chain. Pure-state library, real ed25519 verifier, borsh wire codec (crates/coincync-rolling-finality), and validate_block reorg-rule integration all shipped — gated by the rolling-finality cargo feature (default OFF). Activation heights per CIP-011: testnet enables at 50,000 and enforces at 75,000; mainnet at 25,000 / 50,000.

CoinCync Improvement Proposals
Every protocol change goes through a public CIP. Anyone can submit one. The list below is the live state of every proposal in the repo.
How decisions actually get made: Discussion happens publicly on Discord / Matrix / GitHub. Maintainers review for cryptographic and constitutional fit. Activation requires 95% miner version-bit signaling at the fork height (Article XIV). Node operators have the final say by choosing whether to upgrade. There is no token-weighted vote, no foundation override, no admin authority. Article XVIII of the Constitution.

Submit a proposal

Anyone can submit a CIP. No fee. No minimum holdings. No identity required.

  1. Fork the repo, add a markdown file at docs/cip/CIP-NNN-short-name.md.
  2. Use CIP-001 or CIP-002 as a template. Required sections: Abstract, Motivation, Status, Mechanism, Security Considerations, Open Questions.
  3. Open a pull request. Maintainers will assign a CIP number.
  4. Discuss in Discord or on the PR thread.
  5. Standards-Track CIPs require 60+ days of public discussion before reaching the activation phase.

Read CONTRIBUTING.md for the full process and what's structurally out-of-scope (stablecoins, smart contracts, bridges, admin keys, governance tokens — see Article XV "Spirit and Construction").

No token-weighted votes. No foundation override. No admin authority. Just public proposals, public discussion, and node-operator opt-in. Article XVIII of the Constitution.
