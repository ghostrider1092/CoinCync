How ASERT works
Short window (70% weight)

20-block window responds quickly to sudden hashrate changes. Prevents large swings from manipulation.

Long window (30% weight)

500-block window provides stability over time. Smooths out variance and temporary hashrate spikes.

Half-life: 60 seconds

Adjustments decay exponentially. A block that is too fast has diminishing influence over time.

Continuous adjustment

Unlike Bitcoin-style 2016-block windows, ASERT adjusts every single block. No cliff effects.

Security model · what's exposed and why
"Client auth: No" does NOT mean "anyone can do anything to the node." It means clients (browsers, mobile wallets, integrators) don't need to manage a bearer token — nginx adds it for them on the way in. The bearer is required at the daemon layer; nginx is the only thing that knows the token. The daemon rejects any request that arrives without it.
  • Read methods (get_info, get_block_range, get_supply_info, etc.) are intentionally public — the explorer, mobile wallets, and integrators all rely on them. Same posture as bitcoin-cli getblockchaininfo over a public RPC.
  • Write methods that mutate consensus state (submit_block, send_raw_transaction) are public by design — that's how mining submissions and transaction broadcasts work on any permissionless chain. Validity is enforced at consensus time, not at RPC admission.
  • Administrative methods that would let anyone harm a node (stop_node, ban_peer, clear_mempool, etc.) are not implemented in coincync-node at all. There's no RPC surface that would let a third party reach into the daemon's process or peer-management state.
For full RPC access without any auth boundary (heavy integrators, dev work), run your own node and point at http://127.0.0.1:28081. See docs/DEVELOPER.md.

Home›Soak status
Operational soak status
72-hour pre-launch and ongoing reliability sampling across the fleet. Numbers update on page poll.
What this measures
Every fleet node samples its own RPC every ~2 minutes and writes a JSONL record: chain tip, peer count, mempool size, partial-broadcast events, stalls. The aggregate across all 5 boxes is the network's operational track record. Zero errors and zero partial broadcasts for a 72h window is the bar for a clean verdict; recovered incidents (peer wedges fixed by restart, deploys mid-soak) are documented in commit history rather than hidden.
